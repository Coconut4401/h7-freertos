# 输入事件合并、限流与队列监控开发日志

## 1. 文档信息

- 项目：STM32H743 5 英寸触摸桌面系统
- 进阶项目：输入事件合并、限流及队列监控
- 记录日期：2026-09-09
- 当前固件诊断模式：`APP_DIAGNOSTIC_MODE = 0U`
- 文档用途：记录功能设计、开发过程中出现的缺陷、排查过程、解决方式及实机测试结果

> 状态说明：本文将问题分为“已解决”“已定位待修复”和“待继续定位”。未完成实机复测的问题不记为已解决。

## 2. 功能目标与实现概要

本进阶项的目标是在鼠标和触摸屏产生大量输入事件时，避免 GUI 任务被无意义的连续移动事件占满，同时保证点击、松开、返回和设备连接状态等关键事件不丢失，并通过监控页面量化调度效果。

当前实现包括：

1. 使用长度为 32 的统一输入队列接收触摸、鼠标及测试事件。
2. 为关键事件预留 8 个队列位置。
3. 对连续 MOVE 事件采用“保留最新坐标”的生产者合并。
4. 消费者取出事件时，再折叠队首连续且来源相同的 MOVE 事件。
5. 根据队列深度执行自适应限流：
   - 深度 0～7：MOVE 间隔 10 ms；
   - 深度 8～15：MOVE 间隔 16 ms；
   - 深度 16～23：MOVE 间隔 33 ms；
   - 深度达到 24：进入保护模式，优先保留关键事件空间。
6. MOVE 等待超过 50 ms 后按过期事件处理；滚轮等待超过 100 ms 后丢弃。
7. 统计 RAW、SENT、MERGED、THROTTLED、EXPIRED、DROP、CRITICAL DROP、队列当前值/峰值以及平均/最大延迟。
8. 增加 INPUT SCHEDULER 监控页面，并提供 `CAPTURE 60S`、`FLOOD 10S` 和 `RESET STATS` 操作。

## 3. Bug 与排查记录

### 3.1 FLOOD 后页面狂闪、统计显示异常、鼠标失控

**状态：已解决，并已通过现象复测。**

#### 现象

- 在 INPUT 监控页面点击 `FLOOD 10S` 后，页面出现高频闪烁。
- RAW、MERGED 等统计数字显示异常，存在被覆盖的视觉效果。
- 鼠标光标自行乱转。
- 退出监控页面后，仍需等待一段时间才恢复正常。

#### 分析与排查

FLOOD 会持续生成大量模拟 MOVE 事件。如果模拟事件与真实鼠标事件使用相同的业务处理路径，就会产生两个问题：

1. 测试坐标被当作真实光标坐标处理，造成光标自行移动；
2. 高频数据触发过多的界面绘制，动态内容、光标保存区域和静态布局可能互相覆盖，导致闪屏和残影。

排查时将“输入队列压力测试”和“实际 UI 操作”拆开处理。FLOOD 的目的只是验证队列、合并和限流机制，不应真正操作桌面或应用。

#### 解决方式

- 为压力测试事件增加独立来源 `APP_INPUT_SOURCE_TEST`。
- 测试事件仍进入统一输入队列并参与 RAW、SENT、MERGED、THROTTLED、队列峰值和延迟统计。
- Runtime 层不使用测试来源更新真实鼠标位置，也不让测试事件触发普通应用功能。
- INPUT 页面刷新动态数值前先隐藏光标，刷新完成后恢复光标，避免动态区域与光标背景缓存互相覆盖。
- 将静态布局绘制和动态数值刷新分离，减少整屏重复绘制。

#### 解决结果

- `FLOOD 10S` 运行时测试数据可以正常增长。
- 测试坐标不再控制真实光标。
- FLOOD 结束后队列可以排空，鼠标无需等待较长时间即可继续使用。
- 2026-09-09 实机测试中，FLOOD 页面、鼠标响应及测试结束后的恢复现象均正常。

### 3.2 INPUT 页面排版越界及 TEST PASS 压住页眉

**状态：已解决。**

#### 现象

- `TEST PASS` 显示位置过高，压到顶部黑色页眉。
- INPUT SENT 等内容所在的黑色面板没有完整覆盖 THR、EXP 等字段。
- 页面横向空间不足，多个字段拥挤。
- RAW/SENT/MERGED、QUEUE/PEAK、THROTTLED/EXPIRED 三个面板的下边缘凸出。
- CAPTURE 60S 所在大框的上边线在 TEST STATUS 一侧被黑色区域覆盖。

#### 分析与排查

新增监控字段沿用了 SYSTEM 页的局部区域，但 INPUT 页的信息量、字号和分组方式不同。部分面板的背景清除范围、边框范围和文字基线没有采用同一套坐标，动态刷新时还可能清除相邻边框。

#### 解决方式

- 将输入调度信息移至独立的 INPUT SCHEDULER 页面，不再强行塞入 SYSTEM 页面。
- 按功能重新分为六个面板：
  - RAW / SENT / MERGED；
  - QUEUE NOW / PEAK；
  - THROTTLED / EXPIRED；
  - LATENCY AVG / MAX；
  - SCHEDULER MODE / INTERVAL；
  - TEST STATUS。
- 重新调整面板坐标、背景范围、边框位置、字号和按钮区域。
- 将三个测试按钮统一放在页面底部，避免测试状态与页眉重叠。

#### 解决结果

INPUT 页面主要面板、页眉和底部按钮已经能够完整显示，未再出现上述越界和页眉覆盖现象。

### 3.3 从 INPUT 返回 SYSTEM 后页面内容互相覆盖

**状态：已解决。**

#### 现象

- 从 INPUT 页面切回 SYSTEM 页面后，原本正确的 SYSTEM 排版被 INPUT 内容覆盖。
- UPTIME、HEAP NOW、INPUT EVENTS 等标题被 RAW/SENT/MERGED、QUEUE/PEAK、THROTTLED/EXPIRED 覆盖。
- 只有退出到桌面再重新进入 MONITOR，SYSTEM 页面才恢复正常。

#### 分析与排查

页面切换时只修改了当前页面标志或更新动态数值，没有重建目标页面的完整静态布局。旧页面像素仍留在显存中，而目标页面的局部刷新不足以清除这些内容，因此形成跨页面残留。

#### 解决方式

- 使用独立页面状态记录当前是 SYSTEM 还是 INPUT 页面。
- 每次切换页面时先重建目标页面的完整静态布局，再写入目标页面动态数据。
- INPUT 页面设置“静态布局是否已绘制”标志；正常定时刷新只更新动态区域。
- 返回 SYSTEM 时显式调用 SYSTEM 布局重绘，而不是仅刷新 SYSTEM 数值。

#### 解决结果

SYSTEM 和 INPUT 可以相互切换，原页面内容不会继续残留到目标页面；退出 MONITOR 再进入也能正常显示。

### 3.4 SYSTEM/INPUT 切换后测试状态和倒计时上下跳动

**状态：已定位，待修复和实机复测。**

#### 现象

运行 CAPTURE 或 FLOOD 时，在 INPUT 和 SYSTEM 页面之间切换，测试状态文字及倒计时数字会一会儿在上、一会儿在下。

#### 分析与排查

源码检查发现，INPUT 页面“首次完整绘制”和“后续定时刷新”使用了不同的纵坐标：

| 内容 | 首次完整绘制 Y 坐标 | 定时刷新 Y 坐标 |
| --- | ---: | ---: |
| 测试状态文字 | 336 | 328 |
| 倒计时数字 | 366 | 356 |

页面切换后会触发一次完整绘制，因此内容先出现在较低位置；下一次监控刷新又按另一组坐标绘制，于是产生上下跳动。该问题属于绘制坐标不一致，与倒计时计算、输入队列或 FreeRTOS 调度无关。

#### 拟采用的解决方式

- 将首次完整绘制与定时刷新共用同一组测试状态坐标常量。
- 统一测试状态动态区域的清除范围，确保旧位置的文字被完整清除，同时不覆盖面板边框。
- 修复后依次执行 CAPTURE 和 FLOOD，并在倒计时期间连续切换 SYSTEM/INPUT 页面验证。

#### 通过条件

- 测试状态文字和倒计时位置固定；
- 数字变化不留下残影；
- 页面切换后第一次刷新不发生位移；
- TEST STATUS 面板和底部按钮边框不被覆盖。

### 3.5 播放 WAV 时非预期退出音乐界面或突然暂停

**状态：待继续定位，尚未解决。**

#### 现象

播放 WAV 文件期间，在没有主动点击 BACK 或 PLAY/PAUSE 的情况下，系统偶尔会：

- 自动退出音乐界面；或
- 音乐突然进入暂停状态。

#### 已完成的代码分析

1. 音乐暂停命令只在音乐页面收到 `APP_INPUT_EVENT_DOWN`，且坐标落在 PLAY/PAUSE 区域时提交。
2. 退出音乐界面由 `APP_INPUT_EVENT_BACK`，或坐标落在左上角 BACK 区域的 DOWN 事件触发。
3. 音频播放状态机自身不会主动把 Runtime 切回桌面。

因此，“退出界面”和“进入暂停”同时指向一个共同方向：系统可能收到了非预期的 DOWN 或 BACK 输入事件。当前输入队列测试结果没有出现积压、关键事件丢失或高延迟，所以暂时不能把该问题归因于队列过载。

#### 当前怀疑方向

- CH9350 鼠标数据中出现异常按键位或串口解析异常；
- 鼠标右键抖动，而当前右键按下会被映射为 BACK；
- 触摸控制器产生幽灵触摸；
- USB-TTL 的 TXD 与 CH9350 TX 同时连接 PA10，形成两个推挽输出冲突；
- USART1 同时承担 CH9350 通信和 `printf` 输出，接线或信号互相影响。

#### 后续排查方案

使用同一 WAV 文件，每组静置播放 10 分钟：

| 组别 | 条件 | 排查目的 |
| --- | --- | --- |
| A | 当前接线，串口状态 ON | 建立可复现基线 |
| B | 当前接线，串口状态 OFF | 判断周期串口输出是否相关 |
| C | 拔掉 USB-TTL，仅保留 CH9350 | 排除 USB-TTL 接线影响 |
| D | 断开 CH9350 TX 或拔掉鼠标，仅使用触摸 | 判断异常事件是否来自鼠标链路 |

发生异常后立即检查：

- LOGS 是否出现 `APPLICATION CLOSED`；
- 音乐状态是否显示 `PAUSED`；
- 是否存在 `DMA ERROR`、WAV 读取错误或 Storage 错误；
- CH9350 的 `sync error`、`discarded frame`、`UART dropped`、连接/断开计数是否增加；
- `HEALTH`、`FSERR` 和 `RESPERR` 是否异常。

#### 预期解决原则

待隔离出异常输入源后再做最小范围修复。未取得分组测试结果前，不修改音频 DMA、WAV 文件格式或输入调度算法，避免影响已经通过的功能。

### 3.6 调试串口与 CH9350 共用 USART1 的接线风险

**状态：风险已确认，已给出安全接线方案。**

#### 现象与风险

项目使用 USART1：PA9 为 TX，PA10 为 RX。CH9350 已连接在 USART1 上。如果 USB-TTL 的 TXD 也接到 PA10，就会与 CH9350 TX 同时驱动 STM32 的 RX，引起乱码、错误鼠标事件，严重时可能造成硬件电平冲突。

#### 解决方式

仅采集日志时采用单向监听：

```text
STM32 PA9 / USART1_TX  -> USB-TTL RXD
STM32 GND              -> USB-TTL GND
USB-TTL TXD            -> 不连接
USB-TTL VCC            -> 不连接
```

串口参数为 `115200 bit/s, 8N1, no flow control`。必须使用 3.3 V TTL 串口模块，不能把 RS-232 的正负电压直接接入 STM32。

- 页面最终状态：测试通过

| 指标 | 实测值 | 判定 |
| --- | ---: | --- |
| RAW | 5188 | 已产生足够数量的真实输入 |
| SENT | 4301 | 小于 RAW，说明输入流量得到压缩 |
| MERGED | 897 | 大于 0，MOVE 合并实际生效 |
| QUEUE NOW / PEAK | 0 / 2 | 停止后成功排空，峰值远低于阈值 28 |
| THROTTLED | 3161 | 大于 0，自适应限流实际生效 |
| EXPIRED | 0 | 本次无事件因等待超时而过期 |
| LATENCY AVG / MAX | 0 / 15 ms | 最大延迟低于 100 ms |
| SCHEDULER MODE / INTERVAL | NORMAL / 10 ms | 测试结束后处于正常调度模式 |
| DROP TOTAL / SEC | 0 / 0 | 无输入事件丢弃 |
| CRIT | 0 | 无关键事件丢失 |
| HEALTH | 31 / 0 | 受监控任务健康，无超时任务 |
| WDG | ON | 独立看门狗处于受控工作状态 |

#### 结果分析

- 合并比例约为 `897 / 5188 = 17.3%`，证明连续移动事件被有效折叠。
- 队列峰值只有 2，说明 GUI 消费速度足以处理真实输入负载。
- 最大延迟 15 ms，距离自动判定上限 100 ms 有较大余量。
- `CRIT = 0` 且 `DROP = 0`，说明本轮没有以丢失点击、松开等事件换取性能。
- MERGED 是生产端与消费端合并计数之和，THROTTLED 是被延后或被更新覆盖的 MOVE 次数；它们与 `RAW - SENT` 的统计语义不同，不要求形成严格等式。

#### 判定

本次 CAPTURE 60S 测试通过。
