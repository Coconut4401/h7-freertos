## 2. 早期硬件与基础功能问题

### 2.1 CH9350 鼠标“USB 有活动但光标不动”

**状态：已解决并由用户确认鼠标可用。**

#### 现象

CH9350 的 USB 活动指示灯 D2 会闪烁，但 STM32 屏幕上的光标不移动，鼠标点击也不能操作桌面。

#### 排查

先确认供电和 UART 接线正常，再检查 CH9350 实际工作状态。原解析器按旧帧格式处理，和模块当前状态 2 的输出不一致。D2 只能说明 USB 侧有活动，不能证明 MCU 已正确解析 UART 帧。

#### 解决方式

- USART1 按 115200 8N1 初始化。
- 增加 UART 接收环形缓冲区和帧同步解析。
- 按当前模块状态 2 解析 7 字节相对鼠标帧：

  ```text
  57 AB 02 Button DeltaX DeltaY Wheel
  ```

- 增加相对位移、边界限制、灵敏度、左键、拖动、滚轮和右键返回处理。
- 在 5 ms 周期内合并多个移动报告，按键和滚轮事件发送前先刷新待发送 MOVE。

#### 接线记录

```text
CH9350 5V  -> STM32 5V
CH9350 GND -> STM32 GND
CH9350 TX  -> PA10 / USART1_RX
CH9350 RX  -> PA9  / USART1_TX
```

当前未实现键盘帧和绝对鼠标帧的业务处理；状态帧的连接/断开业务接入曾列为待补项目。

### 2.2 DS3231 烧录后时间固定变慢/被覆盖

**状态：代码已修复，RTC 实物复测待补。**

#### 现象

每次烧录新固件后，RTC 时间会被重新设置为固件编译时间。编译到烧录之间的时间差表现为固定的慢几分钟。

#### 排查

发现旧启动逻辑使用固件签名或编译时间判断新固件，每次更换固件都覆盖有效的 DS3231 时间。

#### 解决方式

- 删除“新固件必定重设时间”的逻辑。
- 仅在 RTC 数据无效或状态寄存器 OSF 置位时，使用编译时间初始化。
- 增加 SETTINGS 的 TIME 页面，支持年月日时分秒修改、日期合法性检查、闰年处理、星期自动计算、APPLY/CANCEL。
- APPLY 后清除 OSF 并立即更新软件缓存。
- 保持 `SETTINGS.CFG` 数据版本和格式不变，避免产生第二时间源。

#### 待验证

烧录修复固件后手动校时，断电重启并再次烧录，确认有效时间不会被覆盖。

### 2.3 启动白屏、首屏反复闪烁

**状态：已解决代码风险，仍需最终版本上板确认。**

#### 现象

2026-09-01 首次上板时，启动阶段出现白屏和反复闪烁。

#### 排查

确认在 `lcd_init()` 之前启用了 `UNALIGN_TRP`。工程厂商 LCD/BSP 存在非对齐访问兼容需求，严格对齐陷阱导致初始化阶段异常。

#### 解决方式

正式版本撤销 `UNALIGN_TRP`，保留除零陷阱、BusFault、UsageFault、MemManage、FreeRTOS 栈/堆钩子、故障留存和 IWDG。修正后重新全量编译。

### 2.4 启动首页无法进入密码页

**状态：已定位并完成代码修复，待最终上板复测。**

#### 现象

启动首页显示后不能正常进入密码页面。

#### 排查

定位到最高优先级 HealthTask 的 LSI/IWDG 初始化使用无超时忙等待，可能永久占用 CPU，阻塞低优先级 GuiTask。

#### 解决方式

- 将 LSI/IWDG 初始化等待改为有界等待。
- 等待期间主动让出 CPU。
- 初始化失败后延时重试，不让 HealthTask 永久占用最高优先级。
- 调试器连接时冻结 IWDG，避免断点调试产生无意义复位。

## 3. 稳定性保护功能开发记录

### 3.1 FreeRTOS 栈、堆和断言保护

**状态：已实现，已通过 Arm Compiler 6.24 全量编译；故障注入待实测。**

- `configCHECK_FOR_STACK_OVERFLOW = 2`，检查栈指针和栈填充值。
- `configUSE_MALLOC_FAILED_HOOK = 1`。
- `configASSERT`、栈溢出和 malloc 失败统一写入故障记录并软件复位。
- assert 记录源文件名和源代码行号。
- Input、Gui、Storage、Audio、Monitor、Health、Timer 任务显示历史最小剩余栈。
- 剩余栈低于 128 words 时 MONITOR 标红，并向 LOGS 写一次预警。
- 显示当前堆和历史最低堆，历史最低堆低于 32 KiB 时记录预警。

### 3.2 Cortex-M7 异常与故障留存

**状态：已实现，故障注入和恢复链路待实测。**

- 显式启用 BusFault、UsageFault 和除零陷阱，同时保持非对齐访问兼容行为。
- HardFault、BusFault、UsageFault、MemManage 保存 CFSR、HFSR、DFSR、AFSR、BFAR、MMFAR、PC、LR 和 SP。
- 支持基本栈帧和浮点扩展栈帧。
- 故障记录保存在 `0x38800000` 的 4 KiB Backup SRAM。
- 记录包含 magic、版本、长度、序号、故障类型、任务名、Tick、复位标志、异常寄存器和校验和。
- 启动后将故障摘要写入 LOGS。
- StorageTask 以事务方式生成 `CRASH.LOG`，成功写入后才清除 Backup SRAM 记录。
- SD 不可用时每 5 秒重试，避免一次写卡失败造成故障记录丢失。

### 3.3 任务心跳与 IWDG

**状态：机制已实现，任务挂起注入待实测。**

- HealthTask 每 250 ms 检查任务心跳。
- Input、Gui、Audio 最大无心跳时间为 1.5/1.5/5 秒；Monitor 为 2 秒；Storage 为 10 秒。
- 所有必需任务首次健康后才启动 IWDG，硬件超时约 15 秒。
- 只有全部任务健康时才喂狗；任务超时先保存任务名，再停止喂狗。
- 预期流程为：任务挂起 → HealthTask 记录超时 → IWDG 复位 → 启动后恢复故障记录并写入 LOGS。

### 3.4 存储事务与恢复

**状态：主要机制已实现，掉电/复位注入待闭环。**

- 使用临时文件和备份文件进行事务替换，如 `~DRAW.TMP/.BAK`、`~LOG.TMP/.BAK`、`~CFG.TMP/.BAK`、`~FLT.TMP/.BAK`、`~TXT.TMP/.BAK`。
- 启动和读路径执行恢复检查，目标是在旧完整文件和新完整文件之间选择，避免接受半写文件。
- 设置文件包含版本和 CRC/合法性检查。
- 绘图数据带 CRC32，损坏数据拒绝加载。
- SD 错误会将 Storage 标记为 ERROR，并由下一请求重新挂载。

### 3.5 存储、输入和监控字段

MONITOR 当前提供：

- `DROP TOTAL / SEC` 与 `CRIT`；
- `INPUT QUEUE NOW / PEAK`；

## 5. 当前已知风险与注意事项

1. 工程当前不是 Git 仓库，修改前应保留快照，不能使用 Git 回滚覆盖用户文件。
2. SDMMC 轮询传输期间会关闭总中断，可能影响 I2S DMA 和输入实时性。
3. LCD 为单帧缓冲，页面切换不具备双缓冲/VSync 原子交换。
4. USART1 同时承担 CH9350 和 `printf`。USB-TTL 只监听日志时接 PA9→RXD 和 GND，不能把 USB-TTL TXD 与 CH9350 TX 同时接到 PA10。
5. 3.3 V TTL UART 才能直接连接 PA9/PA10，不能把 RS-232 正负电压直接接入 MCU。
6. 右键按下被映射为 `BACK`，鼠标右键抖动可能被表现为意外退出应用。
7. CH9350 D2 只反映 USB 侧活动，不能单独证明 MCU 正确解码。

## 6. 进阶部分：输入事件合并、限流及队列监控

> 本章为原 `ADVANCED_INPUT_SCHEDULER_DEVELOPMENT_LOG.md` 的最后合并章节。它按统一开发日志格式保留了该进阶项的实现、Bug、排查、实测数据和未闭环问题。

### 6.1 功能目标和实现

目标是在鼠标、触摸屏产生大量事件时，避免 GUI 被无意义的连续 MOVE 占满，同时保证点击、松开、返回和连接状态等关键事件不丢失，并通过监控页面量化效果。

当前实现：

1. 长度 32 的统一输入队列。
2. 预留 8 个位置给关键事件。
3. 生产者保留最新 MOVE 坐标。
4. 消费者折叠队首连续同源 MOVE。
5. 按队列深度使用 10/16/33 ms 自适应 MOVE 限流；深度达到 24 时进入保护模式。
6. MOVE 超过 50 ms、滚轮超过 100 ms 未发送时按过期处理。
7. 统计 RAW、SENT、MERGED、THROTTLED、EXPIRED、DROP、CRITICAL DROP、队列当前/峰值和延迟。
8. 提供 INPUT SCHEDULER 页面、`CAPTURE 60S`、`FLOOD 10S` 和 `RESET STATS`。

### 6.2 Bug：FLOOD 后页面狂闪、统计异常和鼠标失控

**状态：已解决，并已通过现象复测。**

#### 现象

点击 `FLOOD 10S` 后页面狂闪，RAW/MERGED 显示异常，鼠标乱转，退出后过一段时间才恢复。

#### 分析

洪泛测试持续生成模拟 MOVE。如果测试事件沿用真实鼠标业务路径，测试坐标会移动真实光标并触发应用逻辑；高频整屏绘制还会与光标缓存、动态数字区域互相覆盖。

#### 解决方式

- 使用 `APP_INPUT_SOURCE_TEST` 隔离测试输入来源。
- 测试事件仍进入统一队列并参与统计，但 Runtime 不使用测试来源更新光标和应用业务。
- 动态数字刷新前隐藏光标，刷新后恢复光标。
- 分离静态布局绘制和动态数值刷新，减少整屏重绘。

#### 结果

FLOOD 期间测试坐标不再驱动真实光标，页面和鼠标可操作，测试结束后队列能够排空并恢复正常。

### 6.3 Bug：INPUT 页面排版越界和页眉覆盖

**状态：已解决。**

#### 现象

`TEST PASS` 压到黑色页眉；SENT、THR、EXP 等内容超出面板；三个黑色方框下边凸出；CAPTURE 大框白色上边线被 TEST STATUS 一侧覆盖。

#### 分析

新增字段沿用 SYSTEM 页坐标，面板背景清除范围、边框和文字基线不一致，动态刷新还可能清除相邻边框。

#### 解决方式与结果

将输入信息独立到 INPUT SCHEDULER 页面，重新分成六个面板，统一调整面板坐标、边框、字号和底部按钮区域。修复后主要面板、页眉和按钮均能完整显示。

### 6.4 Bug：INPUT 返回 SYSTEM 后内容覆盖

**状态：已解决。**

#### 现象

切回 SYSTEM 后 UPTIME、HEAP NOW、INPUT EVENTS 等标题被 INPUT 页 RAW/SENT/MERGED 等内容覆盖，退出桌面重新进入才恢复。

#### 分析

切换页面时只更新了页面标志或局部数值，没有重建目标页面完整静态布局，旧像素残留在显存中。

#### 解决方式与结果

页面切换时显式重绘目标页完整静态布局，再更新动态数据；INPUT 使用静态布局已绘制标志，SYSTEM 返回时重建 SYSTEM 布局。修复后页面可反复切换而不残留覆盖。

### 6.5 Bug：SYSTEM/INPUT 切换时倒计时上下跳动

**状态：已定位，待修复和实机复测。**

#### 现象

CAPTURE/FLOOD 运行期间切换 SYSTEM 和 INPUT，测试状态和倒计时数字一会儿上一会儿下。

#### 排查结果

首次完整绘制和定时刷新使用了不同坐标：

| 内容 | 首次绘制 | 定时刷新 |
| --- | ---: | ---: |
| 测试状态文字 | Y=336 | Y=328 |
| 倒计时数字 | Y=366 | Y=356 |

页面切换后的第一次完整绘制采用第一组坐标，下一次监控刷新采用第二组坐标，因此产生位移。该问题与队列和倒计时计算无关，是 UI 坐标不一致。

#### 解决方式

待统一首次绘制和动态刷新坐标，并统一动态区域清除范围；修复后需在倒计时期间连续切换页面复测。

### 6.6 Bug：播放 WAV 时意外退出或暂停

**状态：待继续定位，尚未解决。**

#### 现象

播放 WAV 期间没有主动点击 BACK 或 PLAY/PAUSE，却偶尔退出音乐界面或突然暂停。

#### 已完成分析

- 音乐暂停只由 PLAY/PAUSE 区域的 `APP_INPUT_EVENT_DOWN` 提交。
- 退出音乐界面由 `APP_INPUT_EVENT_BACK` 或左上角 BACK 区域的 DOWN 触发。
- 音频播放状态机自身不会主动切回桌面。
- 输入队列压力指标正常，暂不能归因于队列积压或关键事件丢失。

#### 当前怀疑方向

1. CH9350 按键位异常或 UART 解析异常。
2. 鼠标右键抖动被映射为 BACK。
3. 触摸控制器幽灵触摸。
4. USB-TTL TXD 与 CH9350 TX 同时连接 PA10。
5. USART1 的 CH9350 通信与 `printf` 输出互相影响。

#### 隔离方案

使用同一 WAV 静置播放 10 分钟，分别执行：

| 组别 | 条件 | 目的 |
| --- | --- | --- |
| A | 当前接线，串口 ON | 建立基线 |
| B | 串口 OFF | 判断日志输出影响 |
| C | 拔掉 USB-TTL，仅保留 CH9350 | 排除 USB-TTL 影响 |
| D | 断开 CH9350 TX 或拔鼠标，仅使用触摸 | 判断异常是否来自鼠标链路 |

异常时检查 LOGS 是否出现 `APPLICATION CLOSED`、音频状态是否为 `PAUSED`、是否有 `DMA ERROR`/WAV 读取错误，以及 CH9350 的同步错误、丢弃帧、UART 丢弃和连接计数。

- `CRIT=0` 且 `DROP=0`，没有以丢失关键事件换取性能。
- MERGED 是生产端和消费端合并总数，THROTTLED 是 MOVE 延后/覆盖次数，与 `RAW-SENT` 不要求严格相等。

### 6.10 Bug：音乐页面光标跳位、播放进度 99%、CH9350 断连抖动与恢复迟钝

**日期：2026-09-11；状态：代码已修复并完成全量编译，最终版待实机回归确认。**

#### 现象

1. 音乐播放时移动鼠标，特别是退出音乐页面以后，光标会突然跳到不确定的位置。
2. WAV 播放结束后，进度数字停在 `99%`。
3. LOGS 在同一秒内反复记录鼠标断开和重连；轻碰线材、但没有真正拔出鼠标时也可能触发。
4. 第一版断连防抖修改后出现回归：断连事件更多；上电进入密码页面后需要移动多次才能识别鼠标；显示离线时仅移动鼠标不能恢复，通常必须按键才恢复。
5. MONITOR 将错误项扩展为 `ERR F/S/D/H` 后，H 的数字与后面的 `HEALTH` 标签重叠。
6. 第二版为了抑制误报而完全忽略 `0x86` 后，真正拔掉鼠标又无法检测断连。

#### 根因与失败方案复盘

- 退出音乐页面的 `BACK` 事件能够改变页面，但 Runtime 没有在处理该事件前同步事件携带的最新鼠标坐标。桌面重绘后继续使用旧坐标，表现为光标跳位。
- 播放进度采用整数除法。播放过程中最后一次已发布进度可能自然落在 `99%`；如果自然播放完成没有单独发布完成状态，界面就不会显示 `100%`。
- CH9350 状态 2 的相对鼠标报告为 `57 AB 02 Button DeltaX DeltaY Wheel`。`57 AB 80 xx` 是状态变化帧，`xx` 低四位为 Report ID；相对鼠标 Report ID 为 `0x02`。实机同时证明 `57 AB 86` 会在鼠标拔出时出现，因此不能完全忽略。
- 第一版把单个 `0x86` 在 200 ms 后直接确认成断连，条件过宽，容易把瞬时接触抖动记成断连。
- 第一版还要求离线后在 100 ms 内连续收到两份鼠标报告才确认重连。普通移动可能只产生零散报告，而按键更容易连续上报，因此造成“移动无效、按下才恢复”。
- 第一版在上电、断开候选取消和重连时强制设置 `report_rebaseline`，导致第一份合法移动报告只用于重置按键状态，位移被丢弃。
- 第二版依据通用协议资料完全忽略 `0x86`，与当前实机模块的实际拔出通知不符，导致真拔出无法检测。
- MONITOR 同一坐标 `x=420, y=407` 同时绘制 UART 硬件错误数和 `HEALTH`，属于固定布局冲突。

#### 最终解决方式

CH9350 连接状态机调整如下：

1. 第一份合法相对鼠标报告立即标记在线、立即处理本帧位移，不再要求双帧确认，也不因上电或正常重连丢弃首帧。
2. 合法鼠标报告会立即取消尚未到期的断开候选，所以瞬时接触恢复后不会产生断开/重连日志。
3. 明确属于鼠标的 `0x80` 状态变化帧，以及实机确认的 `0x86` 拔出通知，都只启动断开候选，不立即宣布离线。
4. 断开确认窗口改为 1000 ms。窗口内始终没有合法鼠标报告才产生一次 `MOUSE DISCONNECTED`；重复通知不重置计时，也不重复产生连接事件。
5. 已离线后收到第一份合法鼠标报告便立即产生一次连接事件并恢复移动，无需按键。
6. 只有协议同步错误、UART 硬件错误或 RX 环形缓冲区丢字节时才设置 `report_rebaseline`，丢弃一份可能由坏帧拼出的可疑位移，正常连接路径不使用该保护。
7. 确认断连时取消待发送的鼠标 MOVE 和滚轮事件，并释放已接受的按键状态，避免断开前的残留输入在之后被发送。

其他关联修复：

- Runtime 在鼠标 `DOWN`、`MOVE` 或 `BACK` 事件进入页面业务前同步最新坐标；右键退出音乐页面后，桌面光标保持在退出时的实际位置。
- 音频播放中进度最高显示 `99%`；只有文件自然播放完成时设置完成标志、将已播放数据量对齐到总量并显示 `100%`。手动停止、出错或中途关闭不伪装成播放完成。
- MONITOR 恢复紧凑的 `ERR F/S/U` 三列。`U` 是 UART RX 丢字节数与 PE/FE/NE/ORE 硬件错误数的饱和和；D/H 分项仍保留在 `ch9350_stats_t` 和串口诊断输出中。删除第四个分隔符和重叠的 H 数值，`HEALTH` 保持从 `x=420` 开始。

#### 关键文件

- `Drivers/BSP/CH9350/ch9350.c`：帧解析、断开候选、延时确认、即时重连和错误后基线保护。
- `Drivers/SYSTEM/usart/usart.c`：USART1 PE/FE/NE/ORE 硬件错误计数。
- `App/app_input.c`、`App/app_mouse.c`：断连时取消残留输入，串口异常后重置鼠标报告基线。
- `App/app_runtime.c`：在页面退出前同步鼠标最新坐标。
- `App/app_audio.c`、`App/app_ui.c`：自然完成状态和 100% 进度显示；MONITOR 错误项布局。
